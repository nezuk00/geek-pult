# Телеграм-пульт

Личная новостная редакция для Telegram-канала. Владелец задаёт тему, приложение ищет публикации и само обнаруживает издателей, а редактор проверяет материал, готовит пост и отправляет его в подключённый канал.

## Как это работает

1. Запустите проект и войдите в закрытую редакцию.
2. В настройках задайте тему словами, например «городская среда и транспорт», «нейросети в медицине» или «инди-игры». Не нужно заранее составлять список сайтов.
3. Приложение собирает результаты Google News RSS и автоматически добавляет обнаруженные издательства на вкладку «Источники». Их можно отключать по одному. Издатели появляются по мере нахождения публикаций.
4. Редактор проверяет исходную статью, факты и повторы, пишет короткий самостоятельный пост и подбирает существующую тематическую картинку. Неподтверждённые или устаревшие материалы пропускаются.
5. Подключите Telegram-канал и бота. Перед отправкой приложение проверяет адрес канала, права бота, паузу автопилота и интервал между постами.

Тематический поиск не означает автоматическую проверку надёжности издателя. Подпись публикации должна ссылаться на прямую статью новостного сайта; ссылки на Telegram-каналы не публикуются. Google News RSS предназначен для личного некоммерческого просмотра; его условия использования могут не подходить для коммерческого сервиса. Каталог не заменяет первоисточник.

## Что входит в проект

- Поиск новостных материалов по теме и автоматическое обнаружение доменов издателей.
- Управление найденными издателями и общий поток материалов.
- История редакционных циклов и отправленных сообщений.
- Проверки свежести, похожих заголовков, URL и ссылок на Telegram.
- Предпросмотр текста и существующего изображения, происхождение картинки и подпись с ограничением Telegram.
- Зашифрованное хранение токена Telegram Bot API.
- Защищённая отправка с двухчасовым интервалом и блокировкой повторов при неизвестной доставке.

## Ограничения автономности

Сборщик приложения может работать по запросу редактора. Для регулярного фонового сбора нужны работающий хостинг и настроенный планировщик. Подготовка текста, проверка смысла, подбор изображения и публикация требуют настроенного редакторского цикла (например, запланированной задачи Codex). Если хостинг или редактор недоступен, цикл должен пропускаться, а не отправлять непроверенный текст.

## Запуск для разработки

Требуется Node.js 22.13 или новее.

```sh
npm ci
npm run dev
```

Конфигурация базы и размещения зависит от выбранной платформы. Для Cloudflare Workers понадобятся D1 и секрет `SETTINGS_KEY` — base64 от 32 случайных байт. Локальные секреты задаются в `.env`; не коммитьте `.env`, токены бота, данные канала, `AUTOPILOT.md` или `.openai/hosting.json`.

Для собственных редакторских правил скопируйте [AUTOPILOT.example.md](AUTOPILOT.example.md) в приватный `AUTOPILOT.md` и настройте тему, источники, временные окна и проверку. Файл примера не содержит настроек реального канала.

## Проверки

```sh
npm run lint
node node_modules/typescript/bin/tsc --noEmit
node --test tests/core.test.mjs
npm run build
```

Тесты используют локальную SQLite и подменённый Telegram API. Они не отправляют настоящих сообщений.

## Безопасность и развёртывание

Читай [SECURITY.md](SECURITY.md) до подключения бота. Доступ к редакции должен быть закрыт для посторонних; `SETTINGS_KEY` хранится только в переменных окружения хоста. Настройте D1-миграции, закрытую аутентификацию и свой расписанный сбор отдельно от GitHub Actions. CI проверяет код и не подключается к Telegram.
